# B2 офлайн: какой дешёвый пакет рефлекса ехать на GPU — записка

*2026-09-26 · Офлайн-отбор по правилу, записанному до данных ([спек](../superpowers/specs/2026-09-26-b2-offline-design.md), §6 и журнал изменений) · Данные: `results/b2/offline/` · Mac CPU, seed'ы 4000 + i, 12 уровней × 512 состояний × 4 прогона, k = 1…7, ≈ 53 мин*

**Как читать числа:**
- **res** — остаток против свежего вызова: ‖exec(a*) − exec(nom + clip(J·e))‖², действия сравниваются как исполненные, как в E1b.
- **R** — какую долю выигрыша точного `J` над pred сохраняет кандидат: (res_pred − res_c) / (res_pred − res_reflex). Считается по уровню из пуловых сумм по парам с ‖e‖ ≤ 2.3 и k ≤ 7, затем берётся медиана по уровням. 1 — как точный reflex, 0 — как без `J`, < 0 — хуже, чем без `J`.
- **Глубина** — последовательные шаги потока после чанка и предсказателя, прямой и обратный шаг считаются за 1. У точного reflex 10, у pred 5.
- **FE** — прогоны сети на вызов, VJP за 2. У точного reflex 330.

**Проверки перед чтением:**
- **Прогон на 128 состояниях** не прошёл проверку на оракуле (0.40 против 0.578 ± 0.1). Разбор показал, что дело в выборке состояний, а не в коде. По решению владельца прогон повторён на 512 состояниях, а первый не читался (журнал спека).
- **Проверка на оракуле на 512 состояниях прошла, но на самой границе:** ρ_clip точного reflex при k = 1…4 равна 0.478 против 0.578, разница 0.0996 при допуске 0.1.
- **Детерминированная сверка кода.** Точный reflex в `b2.py` и `diag.py` на одних и тех же состояниях, z и шуме совпадает до нуля: 3 уровня × 6 состояний, все величины (`scripts/check_b2_vs_diag.py`, `results/b2/offline/exact_check.txt`).

## 4. Строки ширины

- **Один `J` на все позиции:** R −0.11, лучше pred только на 5 уровнях. `J` заметно меняется от позиции к позиции: чужой `J` вредит сильнее, чем его отсутствие. Кроме позиции 5, где он свой. Экономия ширины таким способом не работает.
- **Chunk + J** — номинал из чанка, как у `rtc_reflex`: R −1.06. Пол номинала чанка офлайн намного выше, чем у переспроса. В замкнутом цикле B1 `rtc_reflex` работал, но его чанк — чанк RTC, не политики, и цикл поправляет по пути. Это только опорная строка.

## 5. Что это значит для B2+B5

- **По правилу на GPU едут M3 и T3,** плюс точный reflex, pred и `rtc_reflex`.
- **Отмечено до GPU: пропуск M3 хрупкий.**
  - Он не проходит без 5% хвостовых состояний.
  - Не проходит с оракулом.
  - На ближних позициях у него пол номинала: R 0.44 при k = 1.

  Если в замкнутом цикле M3 проиграет T3, это ожидаемо.
- **Глубина против точного reflex** (10): T3 — 8, то есть −20%, при точном номинале; M3 — 6, −40%.
- **Грубая оценка задержки** — интерполяция по замерам B1 (`results/b1/gpu/cost.txt`: RTX 4090, batch 1, d = 1, s = 1, 4, 7).
  - T3 оставляет 3 из 5 обратных шагов: r_T3 ≈ r_pred + ⅗·(r_reflex − r_pred) ≈ 1.49–1.58.
  - У M3 ещё и на 2 прямых шага меньше: r_M3 ≈ r_T3 − ⅖·(r_pred − r_naive) ≈ 1.32–1.39.

  Цель r ≤ 1.2 не достигается. Это прикидка, настоящую задержку меряет GPU.
- **Следствие для B5.** При r ≈ 1.5–1.6 у T3 честная по задержке сетка при d = 3 невозможна:
  - d′ = ⌈r·3⌉ = 5;
  - нужно s ≥ d′ и s + d′ ≤ 8, то есть s ≥ 5 и s ≤ 3 одновременно.

  Честное сравнение по времени остаётся только при d ≤ 2, где выигрыш рефлекса мал. Поэтому первый вопрос спека B2+B5 — идея «`J` вне критического пути»: исполнение стартует по номиналу pred (r ≈ 1.1), а `J` включается на тех позициях, до которых успел досчитаться.
- **Граница честной сетки при d = 3: r ≤ 4/3 ≈ 1.33** (d′ = 4, s = 4). M3 стоит у самой границы, а при d = 3 его R 0.86–1.03. Значит, измеренная на GPU задержка M3 решит, возможна ли такая сетка вообще.
- **Где проваливается M3** (`by_k.csv`). В основном на k = 1–2: R 0.44 и 0.63. На позициях k = 3…7, которые исполняются при d = 3, R от 0.86 до 1.03.
  - **Прогноз для B2+B5** (записать в его спек до данных): при d = 3 M3 близок к T3, при d = 1 заметно хуже.
- **Идея на потом, не проверялась:** T3 + номинал π(ô) — это pred плюс три обратных шага. Глубина pred уже ≈ 1.1 RTC. Значит, дешевле T3 при том же качестве можно стать, только если убрать обратные шаги с критического пути, например считать `J` параллельно следующему вызову.

## 6. Ограничения

- **Офлайн, один чанк, открытый цикл.** Сравнивается одно действие, а не эпизоды.
- **Хвосты.** 5 состояний из 128 несли около половины суммы pred на уровне. Поэтому объём подняли до 512, а описательная проверка без 5% хвостов меняет выбор.
- **Проверка на оракуле прошла на границе допуска.** Код подтверждён точной сверкой с `diag.py`, но выборочная величина шумная.
- **Модели мира маковские,** не подовские из B1. SHA-256 в замке конфигурации, файлы в репозитории.
- **Единица глубины f = b = 1 — упрощение для порядка в правиле.** Оценки задержки выше — интерполяция по замерам B1, а не по этой единице.
