## 1. Зачем

В статье заявлено покрытие классов помех. Корректор, масштабируемый скоростью предмета (PPC), структурно слеп к скачку. Наш корректор масштабируется смещением и покрывает оба класса. Два прогона защищают это заявление от двух возражений рецензента:

1. **«Ваш PPC урезан».** Докстрока `_ppc_measure` прямо признаёт: «no 2-EMA latch stabiliser». Латч — штатный механизм их статьи: он ограничивает длину исполняемого чанка при устойчивой неровности движения. Мы добавляем его отдельной веткой (PPCL) и гоним во всех клетках, где в статье показан PPC.
2. **«Чем ваш рефлекс отличается от классического регулятора поверх VLA с подобранным коэффициентом?»** Нужен ответ числом. Ветка VS — наш G-auto, из которого снят ровно один наш компонент: закон З1 (самонастройка κ по теневому измерению). Вместо него — фиксированный κ = k, подобранный перебором на отложенных данных.
   - Разброс κ̄ по мозгам в части 2 — в 4.5 раза (π 0.306, OFT+ 0.121, OFT 0.088). Поэтому VS идёт в двух версиях:
     - **VS-общий:** один k на все мозги и клетки;
     - **VS-подогнанный:** k подобран под каждый мозг.
   - VS-подогнанный и G-auto получают одни и те же данные: те же 60 калибровочных случаев M0 мозга, на которых считалась κ̄. Отличаются они законом (фиксированный κ против З1) и способом получения числа (перебор трёх кандидатов эпизодами против теневого измерения).

## 3. Новые ветки

Существующие реализации G, G-auto и PPC не меняются ни в одной строке поведения. Новые ветки добавляются рядом, по образцу PPC9 (их приложение A.9): своё имя метода, свои ветвления. Тесты (§13) проверяют побитно, что прежние ветки не изменились.

### 3.1 PPCL — PPC с латчем по статье (arXiv 2605.11459, §3.4 и приложение A.10)

- **Всё от PPC без изменений:**
  - темп через горизонт исполнения K_exec (`ppc_next` = t_obs + K_exec);
  - путь (профиль Фибоначчи, K = 2);
  - замер скорости в `trigger`;
  - отступы на обрезанном действии;
  - работа до первой команды «закрыть».
- **Состояние латча (C, L, m)** обновляется на каждом сбросе чанка — когда новый план начинает исполняться (`on_new_chunk`):
  - **замер:** v_N = p(t_obs,N) − p(t_obs,N − 1) — одношаговая скорость предмета на шаге наблюдения плана N, как его видит рефлекс. У них «скорость из потока трекера» без формулы. При d = 0 это шаг сброса;
  - **триггер:** τ_N = 1[ρ_N < 1/2], ρ_N = max(0, cos(v_N, v_{N−1})), v_{N−1} — замер предыдущего сброса. **Если хоть один из двух замеров не больше `PPC_V_MIN` (1 мм/шаг), τ_N = 0:** у них косинус нулевого вектора не определён, это наше толкование (§14, п. 3). Первый сброс эпизода τ = 0;
  - **внешняя EMA:** C_N = β_out·τ_N + (1 − β_out)·C_{N−1};
  - **липкость** — по уже обновлённому C_N: s_N = C_N / (C_N + R_TH);
  - **внутренняя EMA:** L_N = β_in + (1 − β_in)·L_{N−1} при τ_N = 1, иначе L_N = [1 − β_in·(1 − s_N)]·L_{N−1};
  - **латч:** m_N = 1[L_N > L_th].
- **Константы статьи:**
  - β_in = 0.3 (их единственный свободный параметр);
  - β_out = 1 − 2^(−K/T) = 0.0830 при K = 2, T = 16;
  - L_th = R_TH = β_in·(1 − β_in)² = 0.147;
  - потолок T/4 = 4 шага.
- **Действие латча:** при m_N = 1 следующий вызов наступает не позже t_obs,N + 4 — отдельный срок `latch_next`. Отсчёт от t_obs, как у `ppc_next` нашей PPC. Срок темпа `ppc_next` не трогается; вызов — на шаге min(ppc_next, latch_next). При m_N = 0 `latch_next` = ∞.
- **Сброс у предмета:** на каждом шаге до первой «закрыть», при ‖EEF − p‖ < r_grip = 30 мм, состояние обнуляется: (L, C) ← (0, 0), m ← 0, `latch_next` ← ∞. Если на том же шаге приходит новый план, его обновление латча идёт после сброса и тоже кончается сбросом: внутри r_grip латч выключен. Больше ничего не меняется: темп, путь, отступы, `ppc_next`, последний замер. В A.10 радиус назван «полураствор схвата» без числа. 30 мм — единственное число их статьи для этой зоны: радиус их «grasp gate».
- **Поведение по формулам** (проверяется тестами §13):
  - **устойчивая неровность** (направление на соседних сбросах расходится больше чем на 60°) → τ = 1 на каждом сбросе, латч включается с первого триггера и держится, пока неровность идёт;
  - **выброс величины:** один огромный замер по тому же направлению в равномерном потоке или скачок из покоя (наш M1: один огромный замер, рядом нули) → ни одного триггера, латч не включается, PPCL побитно равен PPC;
  - **одиночный поворот направления** на равномерном движении → один триггер → латч держится **4 чанка** (L = 0.300, 0.241, 0.192, 0.152 > 0.147; пятый 0.119). В тексте A.10(b) сказано «ровно два чанка». Это верно только без липкости (s = 0), и даже тогда L₂ = L_th не проходит строгое «>». По их же формулам с липкостью — 4. Мы реализуем формулы, а не фразу (§4, п. 7). Причина выбора: при расхождении текста и формул взято толкование в пользу PPC — ограничение держится дольше, PPC чаще перепланирует;
  - **выброс направления** (один замер в другую сторону в равномерном потоке) → два триггера подряд → 8 чанков. Так латч и задуман: он реагирует на неровность направления, а не на величину.
- **Важно для ожиданий.** На наших клетках нет устойчивой неровности направления. На LIBERO-MAX скачок одиночный из покоя, на стенде движение прямолинейное с постоянной скоростью. По разбору кода латч почти нигде не включится, и PPCL ≈ PPC (§10). Каждая запись PPCL несёт счётчики латча, сводка даёт долю эпизодов с включённым латчем.

### 3.2 VS(k) — регулятор без закона З1

- **Закон.** VS(k) — ветка κ-семейства `GAgent` с фиксированным κ = k (как G с κ = 1 и Gkeep с κ = 0). Всё, кроме закона З1, — от G-auto:
  - для плана N, наблюдённого после включения t_e, неизвестный план сдвиг U(t) = (1 − k)·Δ_N + (p(t) − p(t_obs,N)); для более ранних планов κ = 1;
  - поправка e = k_p·(U − E), k_p = 1;
  - ограничение шага |e| ≤ |U| / T_ramp, T_ramp = 5;
  - мёртвая зона по |U|;
  - обрезка ±1;
  - C считает отправленное после обрезки;
  - остановка на первой команде «закрыть».
- **Снят только закон З1:** у G-auto κ_N = s_N + κ̄·(1 − s_N) (поправка на долю сдвига, которую рефлекс уже унёс, плюс κ̄ мозга из теневого измерения); у VS κ_N = k на каждом плане.
- **Что оставлено и почему** (решение владельца 2026-10-20: снимается только наше; компоненты, которые есть в любом сервоприводе, остаются, иначе рецензент скажет, что мы выкинули штатный компонент ради нужного результата):
  - **остановка после «закрыть»:** иначе VS тянул бы руку против переноса уже взятого предмета;
  - **мёртвая зона.** Владелец предложил считать её тем же правилом, что пороги шумных глаз в части 2: ≤ 5% эпизодов с ложным включением на неподвижном предмете при s + d = 30, 200 seed'ов (`part2_offline.json → cv.bands`). Правило применимо к VS без пересчёта. Ложное включение — первое срабатывание |p(t) − p(t_obs)| > eps на неподвижном предмете. До первого включения κ не участвует, и U у VS и у G-auto совпадают. Поэтому правило даёт для VS то же число: eps_cv = 22.9 мм на шумных глазах. У оракула шума нет, и правило о ложных включениях от шума вырождено. Берётся 5 мм (`orx.EPS`) — порог всех оракульных веток частей 1–2;
  - **ограничение шага** |e| ≤ |U| / T_ramp. В первом задании было «без ограничения величины». Во втором письме владельца — «снимать надо только наше: закон З1» и «останется единственное различие — способ получения числа». Оставлено, чтобы VS и G-auto различались только законом κ.
- **Решение владельца 2026-10-20 (второй разбор):** ограничение шага и мёртвая зона остаются. Версию VS без мёртвой зоны и без ограничения шага не делаем.
  - Мёртвая зона есть в любом сервоприводе. Поправляться к предмету после «закрыть» не станет ни один регулятор.
  - Собрать заведомо слабый регулятор и победить его — ровно тот упрёк, ради которого мы чиним PPC.
  - На вопрос «чем это отличается от visual servoing» отвечают C6 (перенос коэффициента на другой мозг) и C3 (шум), а не ослабленный конкурент.
- **Наблюдения те же, что у G-auto:** оракул; на стенде @cv — те же CV-глаза (`lead.CVKalman`, один поток кадров на seed эпизода), что у Gauto@cv.
- **Вызовов VS не добавляет:** расписание то же, что у «нет».
- **VS1.0 совпадает с G по коду побитно** (тест §13). VS0.1 и VS0.3 отличаются от G только значением κ после включения.

## 4. Что в нашей реализации PPC остаётся неполным после правки

Этот список идёт в статью. Где мы отличаемся от их статьи после добавления латча (по тексту v1 на arXiv; перед статьёй сверить вручную по PDF):

1. **«Grasp gate»:** при ‖TCP − предмет‖ < 30 мм их обёртка отключается полностью. Наша PPC (и PPCL) поправляет до первой «закрыть». Знак влияния не известен.
2. **Δp — плановый шаг руки.** У них он берётся из реализованной траектории TCP: (p_t − p_{t−K}) / K, с запасным значением на первом чанке. У нас — из обрезанного действия плана × G_POS. Влияет на темп α* и на направление v_⊥.
3. **Фильтр согласованности ν_t:** на телепорте (скорость симулятора 0 при ненулевом смещении) их обёртка держит α = 1, без сжатия. Наша PPC на скачке видит огромную скорость и зовёт мозг раньше. **Это в пользу нашей PPC на клетках со скачком.**
4. **Потолок скорости V_max = 1 м/с** (5 см/шаг при 20 Гц). У нас его нет: скачок 6–12 см даёт замер больше потолка, отступ пути считается от несрезанной скорости.
5. **Геометрия чанка.** У них T = 16, не больше 10 шагов среды на чанк, K_exec ∈ [2, 10]. У нас горизонт — период s (10 у π, 8 у OFT+), K = 2, потолок латча 4 шага взят у них как есть.
6. **Байесовское сжатие темпа** (K_kal). В их симуляции оно выключено заглушкой, на реальном роботе питается уверенностью трекера. Наши клетки латча — оракул, расхождения нет.
7. **Толкования, которых нет в тексте:**
   - триггер латча при замере ниже `PPC_V_MIN` (§3.1);
   - замер для латча — одношаговая скорость на шаге наблюдения плана;
   - r_grip = 30 мм;
   - длительность латча от одиночного триггера: по их формулам 4 чанка, в их тексте «два» (§3.1). Взято толкование в пользу PPC: дольше ограничение, чаще перепланирование.
8. **Мозги.** Их базы дообучены на ≈ 10 тыс. демонстраций MoveBench с движением; наши — замороженные политики LIBERO. Это различие условий, а не реализации.

Пункты 1–6 в этом прогоне не исправляются; это следующий шаг, если рецензент спросит. Утверждать, что наша PPC полная, нельзя.

## 5. Подбор k (правило записано до данных)

- **Кандидаты** — ровно три, общие для обоих мозгов: k ∈ {0.1, 0.3, 1.0}.
  - 1.0 — «новый план знает сдвиг целиком», это G;
  - 0.3 и 0.1 — близко к κ̄ части 2 у π (0.306) и у OFT+ (0.121).
  - Сетка выбрана со знанием κ̄ части 2. Это подарок классике, а не нам: перебор заранее содержит значения, к которым пришло теневое измерение.
- **Данные подбора** (решение владельца 2026-10-20) — **M0 мозга:** его 60 калибровочных случаев LIBERO-MAX (`split.json → calib`: 42 Plus + 18 PRO, все 33 задачи), d = 0, оракул.
  - Это те же случаи, на которых в части 2 считалась κ̄ этого мозга: VS и G-auto получают одинаковый объём информации.
  - С оценкой (`eval`) не пересекаются.
  - Один процесс бегуна на источник: Base до события + три ветки VS0.1, VS0.3, VS1.0 на каждом случае.
  - **Бюджет: 3 × 60 = 180 эпизодов Dynamic на мозг.**
- **Критерий — непрерывный, промах захвата** (предложение владельца: доля успеха на 60 случаях слишком шумная).
  - Годный случай: у всех трёх кандидатов эпизод годен (`prefix_ok`, нет `replay_miss`, событие было, не пропущен) и была команда «закрыть» (`grasp_miss_m` не пуст).
  - Счёт кандидата — средний `grasp_miss_m` (расстояние EEF–предмет в плоскости стола на первой «закрыть», м) по годным случаям. Случаи общие для трёх кандидатов: сравнение парное.
  - Побеждает меньший счёт. Кандидаты в пределах 0.1 мм от лучшего — ничья. Порядок предпочтения при ничьей: 0.3, 0.1, 1.0.
  - Если годных случаев меньше 40, правило применяется всё равно, отчёт это помечает.
- **Кто подбирается:**
  - **k_π** (подбор на M0 π) = **k_общ.** VS-общий = VS(k_π) во всех клетках и у всех мозгов: π (M1, D, стенд, шумные глаза), OFT+, OFT (хвост);
  - **k_OFT+** (тот же подбор на M0 OFT+) → VS-подогнанный у OFT+ = VS(k_OFT+);
  - **у π VS-подогнанный совпадает с VS-общим:** то же правило на тех же данных. Строка 9 хвоста задания («VS-подогнанный на π контрольной строкой») поэтому снята, она ничего не добавила бы.
- **Автоматика.** Подбор считает сводка (`scripts/c1e4c_summary.py --select`) на поде, сразу после строки подбора, до первой оценочной строки. Результат с полными счётами пишется в `results/c1-e4/controls/pod_C/k_select.json`, строки сетки берут метку ветки оттуда. Ручных исключений нет.
- **Совпадения:**
  - k_OFT+ = k_π → VS-подогнанный у OFT+ тождественен VS-общему. Вторая ветка не гоняется, C6 — «не расходятся, тот же k»;
  - выбранный k = 1.0 у мозга, чья проба дала режим П (§7) → VS на M1 при d = 0 этого мозга не гоняется, берётся сохранённый G (§2).

## 7. Парность и повторное использование

- **Пара — (случай, новая ветка) против (случай, ветка-сравнение) того же мозга и (s, d).** Для стенда — (задача, начальное, вид, ячейка) против того же ключа; seed эпизода выводится из ключа (`c1e4b/…/move`), поэтому движение предмета то же.
- **Base прогоняется заново, но только до события.** Записи части 2 хранят только хеш действий (`act_hash`), а не чанки. Без чанков Base Dynamic не может повторить префикс до события. Поэтому каждый процесс LIBERO-MAX сначала гонит Base до события (новый флаг бегуна `--base-prefix`): чанки нужны лишь вызовам до e. Base одной пачки останавливаются вместе — когда событие увидели все Base пачки, то есть по последнему событию в пачке. Тогда у каждого вызова Base до события тот же состав пачки, что в части 2: чанк может зависеть от пачки. Если в пачке есть Base без события, вся пачка идёт до конца, как раньше. У обрезанного Base `success` и `grasp_ok` пусты, остальные метрики покрывают только пройденные шаги, и сводка их не читает. Потом идут ветки с повтором этих чанков — как в части 2.
- **Те же группы и настройки.** Порядок случаев, группы по 6 (часть 2: `n_envs` 6 у всех мозгов), (s, d), ревизии, точность и рендер те же. Тогда пачки вызовов Base совпадают с частью 2. Исключение — у OFT+ последняя группа источника в первых 300: часть 2 шла по всей оценке, и там эта группа полная (187 Plus = 31 × 6 + 1, 113 PRO = 18 × 6 + 5).
- **Карта.** В `conf` части 2 она не записана. По журналу владельца: под A — RTX 4090 (π: LIBERO-MAX и стенд), под B — RTX 3090 (OFT+, OFT, SmolVLA). Новый под — 4090: π — около 80% прогона. Новые записи пишут имя карты в `conf` (`gpu`).

### 7.1 Проба побитности (первый шаг пода, до любой строки)

Повторяем куски части 2 точь-в-точь: та же команда, тот же набор веток, тот же κ̄, те же случаи в том же порядке. Затем сверяем `act_hash` каждого эпизода с сохранённым. Исходы проб не читаются, только хеши и e.

| проба | что повторяем | эпизодов | ≈ ч |
|---|---|---|---|
| π, LIBERO-MAX | первые 2 группы (12 случаев Plus) `M1M2_pi05_eval300_plus_d0`: Base + 7 веток (none, G, Gauto, PPC, G@glr, PPC@glr, T0), κ̄ 0.306 | 96 | 0.52 |
| OFT+, LIBERO-MAX | первые 2 группы (12 случаев Plus) `M1oftplus_oftplus_eval_plus_d0`: Base + 4 ветки (none, G, Gauto, PPC), κ̄ 0.121 | 60 | 0.21 |
| π, стенд | первая задача `Boracle_pi05` целиком: начальные 0–9, ячейки A, A20, ветки none, Gauto, Glead, PPC, κ̄ 0.324 | 80 | 0.32 |

**Правило (до данных), отдельно для каждой пробы:**
- все хеши пробы равны сохранённым → **режим П (повтор)**: ветки-сравнения берутся из части 2, их не гоняем;
- хоть один хеш не равен → **режим С (самодостаточный)**: ветки-сравнения правил гоняются на этом поде заново, в том же процессе и на тех же случаях, что и новые ветки.

Побитность — всё или ничего: частичное совпадение значит, что повтор не точен, и это тоже режим С. Ожидание (не правило): π 4090 → 4090 на закреплённых версиях — скорее П; OFT+ 3090 → 4090 в bf16 — скорее С.

Режимы пишутся в `results/c1-e4/controls/pod_C/mode.json` (`c1e4c_summary.py --probe`), строки сетки читают их оттуда. Проба стенда решает за строки стенда π, проба π LIBERO-MAX — за строки π LIBERO-MAX, проба OFT+ — за строки OFT+.

### 7.2 Что гоняется в режиме С

- **G-auto** — везде, где она сравнение правила или измерения (§8):
  - π: M1 (И1) и D при d = 10, 20 (C2); d = 0 — та же M1;
  - OFT+: M1 (И2, И3);
  - стенд: A + A20 оракул (И4), A20 @cv (C3).
- **VS1.0 вместо сохранённого G** — гоняется сам; подмена на G (§5) — только в режиме П.
- **PPC для C5 полностью не гоняется.** По построению PPCL совпадает с PPC в каждом эпизоде, где латч ни разу не включился: срок `latch_next` остаётся ∞, вызовы и действия те же (тесты 2 и 5, §13). Поэтому PPC гоняется отдельным проходом в конце строки только на случаях (ключах стенда), где у PPCL латч включался хоть в одном эпизоде. Список — из записей PPCL (`c1e4c_summary.py --latched`). На остальных эпизодах исход PPC := исход PPCL.
  - **Стенд:** проход гоняет все начальные 0–9 латч-задачи в обеих ячейках. Состав пачек вызовов совпадает со строкой 7 только у начальных 0–5. В строке 7 PPCL начальных 6–9 шёл в одной пачке со следующей веткой, поэтому у 6–9 общий префикс PPC и PPCL не побитный. Пара там обычная парная: тот же ключ и seed, как пары веток части 2 из разных пачек.
- **«Нет» не гоняется:** VS − нет и PPCL − нет — только отчёт. В режиме С они помечаются «через под».
- **Цена режима С** (темп §12):
  - π: G-auto 900 эпизодов LIBERO-MAX (≈ 4.9 ч) + 780 эпизодов стенда (≈ 2.5–3.2 ч) ≈ $2.7–3.0;
  - OFT+: 300 эпизодов ≈ 1.0 ч ≈ $0.39.

### 7.3 Проверки парности до чтения

1. **По каждому случаю LIBERO-MAX:** e нового Base равно e сохранённого Base. В режиме П несовпадение снимает пару. В режиме С — только в отчёт, пары внутри пода.
2. **`prefix_ok` / `replay_miss`** каждой ветки против нового Base — как в части 2. Выбывшие пары считаются.
3. **Конфигурация:** поля `conf` ветки-сравнения и новой ветки равны, кроме меток веток, `arms`, `gpu`.

**Почему режим П честен.** Новые ветки побитно сравниваются только со своим Base. Проба показала, что платформа воспроизводит часть 2 побитно. Значит, ветки-сравнения на этом поде дали бы те же записи. Пара остаётся парой по случаю: та же сцена, то же событие, тот же seed шума мозга.

## 8. Правила (до данных)

**Проверки перед чтением:**
- **Парность:** §7.3. В режиме П совпадение e ≥ 98% случаев на мозг и клетку. Выбывших пар (`prefix_ok`, `replay_miss`, несовпадение e) ≤ 2% в каждом правиле и каждом измерении, иначе разбор до чтения.
- **Полнота:** ≤ 1% упавших эпизодов в строке, с повтором (часть 2).
- **Подбор:** `k_select.json` получен из записей подбора правилом §5. Сводка пересчитывает его и сверяет: метка VS в каждой записи сетки равна выбранной.
- **Конфигурация:** §7.3, п. 3.

**Как считаются разности.** Как в части 2: п.п., парно, бутстрэп с кластерами по исходной задаче (33 в LIBERO-MAX, 26 на стенде), 2000 повторов, перцентильный 95%. «Одност.» — нижний 5%-й перцентиль. Равенство порогу — проход, «нижняя > 0» — строго.

**Правила** — только там, где исход может дать находку:

| правило | вопрос | условие | на чём |
|---|---|---|---|
| **C2** | расходятся ли G-auto и VS-общий с ростом задержки? | Δ = среднее по d ∈ {10, 20} (G-auto − VS)_d − (G-auto − VS)_0. «Расходятся», если \|Δ\| ≥ 5 и 95% интервал не содержит 0 (направление называется), иначе «не расходятся» | π, те же 300 случаев при d = 0, 10, 20 (кластер — исходная задача, внутри случая три d) |
| **C3** | помогает ли закон З1 на шумных глазах? | (Gauto@cv − VS(k_π)@cv) ≥ +5 и нижняя > 0 → «З1 лучше на шуме»; ≤ −5 и верхняя < 0 → «фиксированный κ лучше на шуме»; иначе «не различимы» | π, стенд A20 @cv, 260 пар |
| **C5** | меняет ли латч PPC там, где он включался? | (PPCL − PPC) на парах, где у PPCL латч включался: 95% интервал не содержит 0 → «меняет» (направление), иначе «не меняет различимо». Меньше 20 таких пар или меньше 5 задач → «не читается: латч почти не включался» | π, пары всех клеток PPCL с включённым латчем (из M1 300 + D 600 + стенд 520 = 1420); кластеры — задачи LIBERO-MAX и стенда |
| **C6** | расходятся ли VS-общий и VS-подогнанный на чужом мозге? | k_OFT+ = k_π → «не расходятся, тот же k»; иначе «расходятся», если \|VS(k_OFT+) − VS(k_π)\| ≥ 5 и 95% интервал не содержит 0 | OFT+, M1, 300 пар |

- **C5 — почему на парах с латчем** (второй разбор 2026-10-20):
  - В эпизоде, где латч ни разу не включился, PPCL по построению совпадает с PPC (§7.2): такие пары — структурные нули.
  - По E1 (§10) на M1 и в D латч не включится. Это 900 из 1420 пар: в пуле эффект со стенда разбавился бы втрое. Занижать число про чужой метод нам нельзя.
  - «Латч включался» — тот же признак, что у `--latched`: латч держал хоть один чанк в эпизоде PPCL. Отбор по нему не смещает разность: до первого включения PPCL и PPC идут одинаково, признак задаётся общей историей пары, а не исходом.
  - Пул всех 1420 пар и разности по клеткам — справочно, в отчёт.
  - Порог «20 пар и 5 задач» защищает от вырожденного интервала: на трёх парах одной задачи бутстрэп даёт интервал нулевой ширины.
- **C2 остаётся парным контрастом, тренд не берём.** Второй разбор предложил вместо него проверку тренда по трём уровням d. Она не годится:
  - при равных шагах d (0, 10, 20) линейный тренд даёт уровню d = 10 нулевой вес (веса −1, 0, +1). Это тот же контраст d20 − d0, на 600 парах из 900;
  - Δ правила C2 уже использует все 900 пар (веса −1, ½, ½);
  - в части 2 эффект рефлекса по d немонотонен (G-auto − нет +7.0 / +19.0 / +12.7 при d = 0 / 10 / 20). Горб при d = 10 линейный тренд пропустил бы.

**Измерения — оценка и 95% интервал, без порога** (второй разбор 2026-10-20). «Насколько мы отличаемся от классики» — это измерение, а не гипотеза. **Порог не назначается, потому что выборка его не разрешает (§9).** При мощности 18–27% при истинном нуле правило «не хуже на 2» требовало бы оказаться лучше на 1.2–2.4 п.п.: это тест на превосходство с чужой этикеткой, он дал бы ложные провалы. Решение записано до данных, а не принято после них.

| измерение | разность | на чём |
|---|---|---|
| **И1** (было C1a) | G-auto − VS(k_π) | π, M1, d = 0, 300 пар. При k_π = 1.0 это G-auto − G части 2, то есть Q4c на первых 300 (§2) |
| **И2** (было C1b) | G-auto − VS(k_π) | OFT+, M1, d = 0, 300 пар — мозг, которого подбор k_общ не видел |
| **И3** (было C7) | G-auto − VS(k_OFT+) | OFT+, M1, d = 0, 300 пар (при k_OFT+ = k_π — пары И2) |
| **И4** (было C4) | G-auto − PPCL | π, стенд, оракул, A + A20, начальные 0–9, 520 пар |

Разность и интервал считаются так же, как у правил. Слов «не хуже» и «лучше» измерение не даёт. Расширение M1 π до 940 пар (§14, п. 5) не берётся.

- **Утверждения** (каждое отдельно, без поправки на множественность — оговорка в записке):

  | утверждение | нужны |
  |---|---|
  | ОБЩИЙ k НЕ ПЕРЕНОСИТСЯ (VS-общий ≠ VS-подогнанный) | C6 «расходятся» |

  - измерения И1–И4;
  - PPCL − нет и VS − нет в каждой клетке;
  - разрез 12 см (и 6 см) для всех разностей M1;
  - PPCL − PPC по клеткам и на всём пуле 1420 пар;
  - G − VS(k) на M1 при d = 0 — фиксированные κ рядом с G-auto;
  - VS@cv − VS (цена шума у регулятора) рядом с Gauto@cv − Gauto (часть 2: −10.8).

## 9. Мощность (до прогона)

Формула части 1: ошибка (стандартная) = 100·k·√(q/n); входы — по разбросу части 2 (Q4c: полуширина 3.0 на 940 парах ⇒ q·k² ≈ 0.22). Двусторонний 95% интервал — ±1.96 ошибки, односторонняя граница — −1.645 ошибки.

| правило | q, k, n | ошибка | проходит при оценке | мощность |
|---|---|---|---|---|
| C2 (\|Δ\| ≥ 5, интервал без 0) | 0.20, 1.2, 300 + 600 | ≈ 3.8 | \|Δ\| ≥ 7.4 | 25% при 5; 56% при 8; 75% при 10 |
| C3 (≥ 5 и нижняя > 0) | 0.20, 1.0, 260 | 2.8 | ≥ +5.4 | 44% при 5; 95% при 10 |
| C6 (\|·\| ≥ 5, интервал без 0) | 0.15, 1.2, 300 | 2.7 | \|·\| ≥ 5.3 | 45% при 5; 84% при 8 |
| C5 (интервал без 0) | пары с латчем, n заранее не известно | ≈ 100·√(0.2/n): 10 при 20 парах, 4.5 при 100 | \|·\| ≥ 1.96 ошибки | — |

**Почему у И1–И4 нет порога (второй разбор 2026-10-20).** Правило «не хуже» (одност. ≥ −2) при этих выборках — тест на превосходство:

| сравнение | q, k, n | ошибка | «не хуже на 2» проходит при оценке | мощность при истинном 0 |
|---|---|---|---|---|
| И1, И2, И3 | 0.15, 1.2, 300 | 2.7 | ≥ +2.4 | 18% (44% при +2) |
| И1 на 940 парах (расширение за $1.7) | 0.15, 1.2, 940 | 1.5 | ≥ +0.5 | 37% — та, на которой провалился Q4c |
| И4 | 0.20, 1.0, 520 | 2.0 | ≥ +1.2 | 27% (65% при +2) |

Чтобы доказать «не хуже на 2», надо оказаться лучше на 1.2–2.4. При истинном равенстве такое правило в 63–82% случаев объявит провал, которого нет. Поэтому И1–И4 — измерения: оценка и 95% интервал. Расширение до 940 пар не берём: мощность 37% та же, на которой провалился Q4c.

- **Подбор k** на 60 случаях по промаху захвата: разница средних промахов между кандидатами — миллиметры при разбросе промаха ~1–3 см на эпизод, ошибка разности ≈ 2–4 мм на 50 парах. Подбор может выбрать не лучший k, если кандидаты близки. Это свойство любого подбора по 60 случаям, и оно одинаково для VS и для κ̄.

## 10. Ожидания (догадки, не правила; ни одной строки в пользу нашего метода)

- **E1. Латч на скачке почти ничего не изменит.** Одиночный выброс скорости из покоя по нашему правилу (§3.1) вообще не даёт триггера. Ожидаем PPCL − PPC ≈ 0 ± 2 на M1 и в D, доля эпизодов с латчем — единицы процентов или ноль.
- **E2. Латч на плавном движении может прибавить PPC заметно.** Но на нашем стенде движение прямолинейное с постоянной скоростью: замеры на соседних сбросах сонаправлены, триггер срабатывает редко. Наиболее вероятно PPCL ≈ PPC.
  - **Формулировка на исход «PPCL не уступает G-auto на плавном движении» (оценка И4 ≤ 0 или её интервал содержит 0) — заранее:** «Корректор по скорости силён при устойчивой скорости — это подтверждение заявления о разных классах помех, а не опровержение. Наше заявление — про скачок: на M1 PPC и PPCL видят скачок одним замером, и их поправка по построению мала.»
- **E3. VS(k_π) на π, скорее всего, сравняется с G-auto** (|G-auto − VS| ≤ 3). Если сравняется — это нормальный исход. Вклад тогда формулируется так: «κ̄ даёт ту же подгонку без прогона на подбор: теневое измерение по 60 случаям вместо перебора k с эпизодами на каждого кандидата».
- **E4. VS-общий на OFT+ и VS-подогнанный у OFT+:** исход не предсказываем. Если k_π ≈ κ̄_π, на OFT+ он может и перекорректировать, и сравняться. Если подбор OFT+ выберет тот же k, что у π, C6 — «не расходятся», и довод «общий k не переносится» отпадает.
- **E5. Шумные глаза.** VS@cv отличается от Gauto@cv только законом κ (те же мёртвая зона и ограничение шага). Наиболее вероятно «не различимы».
- **E6. Задержка.** Расходятся ли кривые, не предсказываем. G-auto отличается от VS только под планами, наблюдёнными после включения. При задержке таких планов до «закрыть» меньше, поэтому разница может и сжаться, и вырасти.
- **E7. k_π = 1.0 вероятен** (VS = G; §2: З1 даёт κ_N между κ̄ и единицей, в части 2 G 51.3 против 49.7 у G-auto). Тогда И1 — это Q4c на 300 случаях; в части 2 на 940 разность была −1.6 [−4.6; +1.4]. Содержание сравнения с классикой тогда — OFT+, задержка и шум. Нормальный исход, не провал.
- **E8. Вызовы мозга.** У PPCL в среднем не меньше, чем у PPC (латч только добавляет вызовы). У VS — как у «нет», G и G-auto.
- **Исход «классика не хуже везде» возможен.** Тогда статья утверждает следующее (записано до данных):
  1. ось задержки и её измерение на настоящей VLA (часть 1);
  2. поправка между вызовами помогает замороженной VLA на чужом тесте: любой разумный закон даёт выигрыш над «нет»;
  3. κ̄ из теневого измерения настраивает поправку под мозг без перебора k. Довод «один общий k на разные мозги не годится» — только если C6 «расходятся»;
  4. реалистичные глаза.

  Утверждение «наш закон лучше классики» из статьи убирается.
- **Если классика лучше** — узнали до рецензии. Статья перестраивается вокруг пп. 1, 2, 4, закон З1 описывается как один из способов настройки.

## 13. Тесты до пода (обязательны; зелёные и закоммичены до того, как под пойман)

**Латч** (`tests/test_objreflex.py`):
1. **Устойчивая неровность** (направление замера на каждом сбросе поворачивается на 90°) → τ = 1 на каждом сбросе, латч включается с первого триггера и держится. Следующий вызов не позже t_obs + 4: trigger на шаге t_obs + 4 истинен, хотя `ppc_next` позже.
2. **Выброс величины не включает латч:**
   - (а) скачок из покоя: один замер 6 см/шаг на сбросе, вокруг нули;
   - (б) один замер в 50 раз больше по тому же направлению в равномерном потоке.

   Ни одного триггера, `latch_next` = ∞. Вызовы, действия и счётчики PPCL побитно равны PPC на той же истории.

5. **Латч выключен** (порог L_th = +∞ через атрибут класса) → PPCL побитно равен PPC на случайных траекториях с неровным движением и поворотами: действия, моменты вызовов, счётчики.

1. **Решено владельцем 2026-10-20:** k подбирается на M0 каждого мозга (и π, и OFT+), критерий непрерывный — промах захвата. Следствие: у π VS-подогнанный = VS-общий, строка 9 хвоста снята.

С другим толкованием («переход неподвижно ↔ движется — тоже триггер») латч включался бы на старте и остановке движения и на нашем скачке — там, где ранний вызов PPC совпадает со сбросом на шаге скачка. Он гоняется целыми группами по 6 случаев (на стенде — все начальные 0–9 задачи), в которых у PPCL латч включался. Тогда пачки его Base совпадают с пачками строки.
