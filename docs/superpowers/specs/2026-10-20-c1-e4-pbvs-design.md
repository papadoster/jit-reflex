# C1-E4, настоящий регулятор с обратной связью (PBVS) рядом с рефлексом — дизайн

*Aleksandr Karpov · 2026-10-20 · Статус: **до данных** · Тип: прогон с измерениями, записанными до данных · Основа: [спек контрольных прогонов](2026-10-20-c1-e4-controls-design.md) (журнал «ветки VS остановлены», `a98beee`), записка [`docs/c1/e4-controls.md`](../../c1/e4-controls.md) · Под: тот же под C (RTX 4090), сразу после строк 2, 3, 7 контрольного прогона*

## 1. Зачем

- **Вопрос рецензента:** «чем ваш рефлекс отличается от visual servoing?».
- **Ветки VS(k) контрольного прогона на него не отвечали.** Это наш G с фиксированной долей сдвига, унаследованной новым планом, а не регулятор по положению схвата. Владелец их остановил до чтения.
- **Теория (Chaumette & Hutchinson, «Visual servo control, Part II», IEEE RAM 2007, «Target tracking», ур. 10–12).** Для движущейся цели закон такой:

  > v = −λ·L̂⁺·e − L̂⁺·∂ê/∂t

  Первый член — обратная связь по измеренной ошибке «схват против цели». Второй — упреждающая компенсация движения цели.
  - **Наш G — второй член** в проинтегрированном виде: накопленный сдвиг предмета, а не скорость. В его контуре нет ни одного замера положения схвата.
  - **Формулировка для записки и статьи (владелец):** «наш рефлекс — это упреждающий член классического visual servoing при эталоне, заданном планом политики; прогон измеряет, что добавляет член обратной связи».
- **В статье PPC (arXiv 2605.11459v2) VS-baseline нет;** их коррекция тоже упреждающая, по скорости цели. Как выбирать регулятор-baseline честно (одна ручка — усиление, подбор на отложенных случаях), взято у Lee, Levine & Abbeel (ICLR 2017, §6.4, прил. C.5). Обзор источников — в записке.

## 2. Закон PBVS (вариант B: эталон из плана мозга)

**Обозначения:**
- x(t) — положение схвата (EEF);
- p(t) — положение предмета, оракул;
- план N — исполняемый на шаге t чанк, его наблюдение t_obs,N; с шага t_a,N (прибытие) он начинает исполняться, с индекса строки t_a,N − t_obs,N;
- G_POS = 0.011 м на единицу действия за шаг (`src/objreflex.py`).

**Эталон (решение владельца 2026-10-20: s* из плана мозга, привязка (б)).**
- **Путь плана:**

  > w_N(t) = x(t_a,N) + M(строки плана N с индекса t_a,N − t_obs,N до t − 1 − t_obs,N)

  Здесь M — модель руки (§3), отклик положения на обрезанные (±1) действия плана. Привязка — к положению руки в момент, когда план начинает исполняться, и к его строкам с этого индекса. При d > 0 так эталон не заставляет регулятор исправлять расхождение старого и нового плана за окно задержки: это не ошибка схвата относительно предмета.
- **Желаемое положение схвата относительно предмета:**

  > s*(t) = w_N(t) − p(t_obs,N)

**Ошибка — в плоскости стола (xy):**

> e(t) = [x(t) − p(t)] − s*(t) = [x(t) − w_N(t)] − [p(t) − p(t_obs,N)]

- Это то же, что вести предсказанную точку захвата плана ĝ(t) к точке захвата, задуманной планом относительно увиденного им предмета. Рука сверяется с путём плана, предмет — с тем местом, где его видел план.

**Поправка:**
- если |e| ≤ δ, поправки нет;
- иначе Δx = −λ·e;
- действие: a_xy = clip(clip(a_план,xy) + Δx / G_POS, ±1), тот же перевод в действие и та же обрезка, что у G.

Высота, поворот и схват берутся из плана.

**Без памяти между шагами:** ни рампы G (|e| ≤ |U| / T_ramp), ни доли κ, ни учёта отправленного E. Ошибку каждый шаг пересчитывают заново по измерению.

**Когда работает:** от включения t_e до первой команды «закрыть», без пространственного порога.
- Включение — тот же детектор, что у G: первый шаг, где |p(t) − p(t_obs)| > 5 мм (оракул) относительно исполняемого плана. После включения регулятор работает до «закрыть», даже когда новый план уже знает сдвиг. Тогда он следит только за исполнением плана.
- **Почему только после события.** До события каждая ветка повторяет записанные чанки Base: на этом стоит парность. Регулятор, действующий до события, менял бы историю, которую повтор предполагает. G устроен так же. Окно одно и то же у обоих, сравнение симметрично.
- Почему нет пространственного порога: он выключал бы регулятор как раз в окне устаревшего плана, где работает G.

**Почему только xy.** Перенос предмета у нас в плоскости стола. Регулятор по высоте у стола давил бы в стол. Это разбиение управления по осям из Part II: плоскость — регулятору, высота — плану.

**Вызовы мозга** — как у «нет»: регулятор их не добавляет.

**Тождество (вывод владельца, записано до данных).** Пусть рука исполняет план точно, а предмет сдвинут на Δ:
- ошибка e = −Δ, поправка = λ·Δ;
- при λ = 1 регулятор за один шаг отдаёт весь сдвиг. Это G с κ = 1 без рампы;
- расходятся они только там, где рука отклонилась от плана не из-за движения предмета: неточное исполнение, контакт, помеха.

## 3. Модель руки и мёртвая зона (правило до данных)

**Калибровочная строка V0.**
- Base на 60 калибровочных случаях M0 π (`split.json → calib`), полные эпизоды, без обрезки по событию: предмет в Base неподвижен.
- В записи каждого эпизода по шагам:
  - x(t), p(t);
  - обрезанное действие плана;
  - шаги прибытия планов и их t_obs.
- Действия Base не меняются: запись — только чтение состояния (тест §9).

**Кандидаты модели M:**

| | модель | откуда коэффициенты |
|---|---|---|
| M_I | интегратор Δx = G·a | `docs/c1/scouting.md` §3: G = 0.0105 / 0.0121 по x / y |
| M_A | ARX Δx_t = G·a_t + B·Δx_{t−1}, начальное Δx — фактический шаг руки перед привязкой | там же: G ≈ 0.0025, B ≈ 0.79 |
| M_I*, M_A* | те же формы, переподогнанные по V0 (наименьшие квадраты по осям x, y, шаги до первой «закрыть») | перекрёстно в 2 сгиба: случаи делятся пополам по порядку набора, коэффициенты подгоняются на одной половине, ошибки считаются на другой |

**Правило выбора (до данных):**
1. Для каждого кандидата и каждого эпизода V0 берётся худший шаг: max |e(t)| по шагам от первого прибытия плана до первой «закрыть» (у M_I*, M_A* — вне сгиба подгонки). На неподвижном предмете e = x − w_N, ошибка исполнения по модели.
2. **Зона кандидата δ_M** — наименьшее δ, при котором худший шаг выше δ не больше чем у 5% эпизодов. При 60 эпизодах — 4-я сверху величина. Это правило ≤ 5% ложных включений, то же, что у порогов G.
3. **Берётся модель с наименьшей δ_M.** Ничья — в пределах 0.5 мм; тогда порядок M_I, M_A, M_I*, M_A* (меньше параметров и без подгонки по своим данным — первым).
4. **Зона регулятора** δ = max(δ_M, 5 мм): 5 мм — порог всех оракульных веток.
5. **Если δ > 15 мм** — это записывается отдельным пунктом как существенное ограничение baseline, в записке и в статье: «мёртвая зона X см против сдвигов 6 и 12 см».
6. Модель, её коэффициенты и δ сводка считает на поде автоматически (`band.json`), до строки подбора. Ручных исключений нет.

**Ожидание по зоне (догадка, не правило).** В таблице §3 скаутинга на 10 шагах у интегратора медиана 13.7 мм, а p90 — 29.3 мм; у ARX — 15.1 и 31.1 мм. В эпизоде 20–50 планов, правило берёт худший шаг. Поэтому δ у моделей из скаутинга, скорее всего, выйдет 3–5 см. Переподгонка по нашим данным может дать меньше.

**Довод ресерчера, записанный рядом** (владелец выбрал правило выше). При оракуле правило ≤ 5% — про шум датчика. Отклонение руки от плана на неподвижном предмете — не ложная тревога, а то, что регулятор и должен исправлять. При такой точке зрения зона — 5 мм. Мы берём правило владельца: зона покрывает и ошибку модели руки. Если она выйдет больше 15 мм, это пишется как ограничение (п. 5).

**Почему зону не убрать иначе.** То, что регулятор добавляет к G, — ровно его реакция на отклонение руки от пути плана. Нижний предел этого сигнала задаёт ошибка модели руки. Эталон, который пересчитывают от фактической руки, гасит обратную связь, и регулятор снова становится G. Эталон из фактического пути Base точен только до первого нового плана после события. Дальше это путь другого плана, а регулятор превращается в teach-by-showing по контрфактическому эпизоду, которого у настоящего робота нет.

## 4. Подбор λ (правило до данных; сетка — решение владельца)

- **Кандидаты** — {0.1, 0.3, 1.0}: доля ошибки, убираемая за шаг. Постоянные времени ≈ 9.5, 2.8 и 1 шаг. При запаздывании руки (≈ 5 шагов) λ = 1 может перелетать. Он остаётся кандидатом, решает подбор.
- **Данные** — строка V1: те же 60 случаев M0 π, d = 0, оракул, Base до события. Ветки PBVS0.1, PBVS0.3, PBVS1.0, δ и модель из V0.
- **Критерий** — как §5 спека контрольных прогонов: средний `grasp_miss_m` по случаям, годным у всех трёх кандидатов. Меньше — лучше. Ничья в пределах 0.1 мм; тогда порядок 0.3, 0.1, 1.0. Если годных меньше 40 — пометка.
- `pbvs_k.json` сводка считает на поде автоматически, до строк V2, V3.
- **Метки веток — `PBVS0.1` / `PBVS0.3` / `PBVS1.0`.** Имя VS не используется: так звались остановленные ветки G с фиксированным κ.

## 6. Измерения (до данных; оценка и 95% интервал, без порога)

Как И1–И4 контрольного прогона: «насколько регулятор отличается от нашего метода» — это измерение. Порог при 300 парах не разрешён выборкой: «не хуже на 2» проходило бы только при оценке ≥ +2.4.

| | разность | на чём |
|---|---|---|
| **Н1** | PBVS − G-auto | M1 π, d = 0, 300 пар |
| **Н2** | PBVS − G-auto | D π, d = 10 и d = 20 (по клеткам и в пуле, 600 пар) |
| **Н3** | PBVS − PPCL | M1 и D (по клеткам) |

Разности — п.п., парно, бутстрэп с кластерами по исходной задаче, 2000 повторов, перцентильный 95%.

**Только отчёт:**
- PBVS − нет по клеткам (через под);
- разрезы 6 / 12 см на M1;
- вызовы мозга;
- поправки PBVS:
  - доля шагов с поправкой после t_e;
  - средняя |e| и её размах;
  - перелёт — смена знака проекции e на направление сдвига;
- промах захвата PBVS против G-auto;
- выбранная модель, её δ и все δ_M, выбранное λ и счёты всех кандидатов.

**Ждут решения владельца** (в смету §8 не входят):
- (а) **ветка VS-T** — teach-by-showing. s* — смещение «схват − предмет» в момент первого «закрыть» в парном Base, закон тот же, ведётся ĝ. Она исправляет ещё и ошибку прицела плана, на которую G не реагирует вообще. Использует привилегированное знание (захват из контрфактического эпизода), это раскрывается. Нужен полный Base. ≈ +$3;
- (б) **ветка G на этом поде** в M1 и D: чистое измерение «что добавляет член обратной связи» — PBVS − G (по выводу §2 — около 0, кроме отклонений руки). ≈ +$1.7.

## 7. Ожидания (догадки, не правила; ни одной строки в пользу нашего метода)

- **P1. PBVS ≈ G** (тождество §2). Если подбор возьмёт λ = 1, регулятор почти совпадёт с G без рампы. Если 1.0 перелетает, будет 0.3 или 0.1: поправка медленнее, чем у G.
- **P2. PBVS − G-auto (Н1)** — примерно как G − G-auto в части 2 (у π G-auto − G = −1.6 [−4.6; +1.4] на 940). **Исход «PBVS не хуже G-auto» нормален, записано до данных:** «наш рефлекс — это упреждающий член классического visual servoing при эталоне, заданном планом политики; прогон измеряет, что добавляет член обратной связи». Тогда вклад формулируется так: G-auto получает свой коэффициент теневым измерением, без перебора, а обратная связь по руке на этих клетках ничего не добавляет или добавляет столько-то.
- **P3. Зона δ, скорее всего, больше 15 мм** у моделей из скаутинга (§3). Если так — пишется ограничением.
- **P4. Задержка (Н2): исход не предсказываем.** Под задержкой план дольше устаревает, а регулятор отдаёт сдвиг без κ. Может быть и лучше, и хуже G-auto.

## 9. Тесты до пода (обязательны)

1. **Тождество:** рука идёт точно по модели, предмет сдвинут на Δ → при λ = 1 поправка равна Δ на первом шаге после включения; при λ < 1 убывает геометрически.
2. **Неподвижный предмет и точное исполнение** → поправка 0 на каждом шаге.
3. **Мёртвая зона:** |e| ≤ δ → поправки нет.
4. **Окно:** до t_e и после первой «закрыть» действия побитно равны плану.
5. **Оси:** высота, поворот и схват не меняются.
6. **Привязка (б) при d > 0:** путь начинается с x(t_a), строки — с индекса d. Расхождение старого и нового плана за окно задержки ошибкой не считается.
7. **ARX:** путь по рекурсии с фактическим начальным шагом; интегратор — частный случай B = 0.
8. **Без регресса:** тесты G, G-auto, PPC, PPC9, PPCL зелёные без правок; act_hash Base не меняется при включённой записи траекторий.
9. **Сводка `--selftest`:**
   - правило выбора модели и δ, включая перекрёстную подгонку и ничью;
   - подбор λ;
   - план строк V0–V3;
   - проверки пар;
   - измерения Н1–Н3 на синтетике с известными разностями.

## 10. В чём не уверен

1. **Зона δ** — главный риск (§3, P3). Если больше 15 мм, регулятор слеп к мелким отклонениям. Это свойство модели руки, а не наш выбор, и пишется открыто.
2. **Модель руки в плоскости:** поворот кисти тоже двигает схват, но в модели его нет. Это ошибка модели, она уходит в δ.
3. **Контакт до «закрыть»:** если схват толкает предмет, p(t) движется, и регулятор на это реагирует. G тоже. Фильтра толчков у оракульных веток нет, как и в частях 1–2.
4. **Перелёт при λ = 1** с запаздыванием руки ≈ 5 шагов.

### 2026-10-20 — до данных, по ходу реализации

- **Двойная отправка сдвига при d > 0.** Найдено исполнителем на игрушечной руке, до данных.
  - **Что происходит.** Берём план, наблюдённый до события, но начавший исполняться после включения. Привязка (б) берёт x(t_a), где рука уже сдвинута поправкой регулятора. Член предмета p(t) − p(t_obs) при этом показывает полный сдвиг. Регулятор отправлял сдвиг второй раз (2Δ вместо Δ), и тождество §2 при d = 10 и 20 ломалось.
  - **Исправление.** План не знает о поправках регулятора, отправленных после его наблюдения. Поэтому его путь привязывается к положению руки без них: x(t_a) − [z(t_a) − z(t_obs,N)]. Здесь z — смещение руки от собственных поправок регулятора по той же модели M, а начальный шаг ARX тоже берётся без скорости поправки.
  - Ошибка по-прежнему считается по фактической руке x(t): обратная связь замыкается на измерении.
  - **При d = 0** (t_a = t_obs) привязка не меняется. У интегратора действия побитно те же, что в первой версии кода.
  - **У модели ARX** начальный шаг пути и при d = 0 берётся без скорости собственных поправок. Причина та же: план после события сам видит предмет и целится в него от текущей руки, а хвост прежней поправки он не учитывает. Если хвост включить в путь, сдвиг отдаётся второй раз, теперь через инерцию руки.
  - Тесты: при d = 10 и 20 суммарная поправка равна Δ, а не 2Δ; на руке ARX смещение от поправок сходится к Δ и ошибка затухает. Намеренные поломки (без вычитания, неверный знак, z без инерции при ARX, скорость поправки в начальном шаге, запись z на шаг позже) тесты ловят.

### 2026-10-21 — уточнения к чтению (вопросы владельца, до чтения исходов PBVS и VS-T)

**1. Поля `g_on` и `c_extra` у PBVS и VS-T не ведутся — намеренно.**
- Это бухгалтерия нашего G: `g_on` — флаг включения его поправки, `c_extra` — накопленная добавка C, которую видит следующий план.

  - команда «закрыть» была.
- **Меньше — лучше.** Кандидаты в пределах 0.1 мм от лучшего — ничья. Из них берётся первый в порядке 0.3, 0.1, 1.0. Если годных случаев меньше 40 — пометка.
- **Как сработало в этом прогоне.** Правило ничьей не понадобилось: λ = 0.3 дал наименьший средний промах сам по себе. Это уточнение к сообщению владельцу, где я ошибочно назвал выбор ничьей; итог тот же.
- **Фраза для статьи:**

  > We chose the servo's gain λ from {0.1, 0.3, 1.0} on the 60 calibration cases by the lowest mean grasp miss (the in-plane gripper-to-object distance at the first close command), averaged over the cases valid for all three candidates; candidates within 0.1 mm of the best would have been resolved by the fixed order 0.3, 0.1, 1.0.

#### B. Ветка VS-T с памятью — решение (формула отдельной записью, до кода)

- **Вариант (в) владельца** — форма ошибки VS-T плюс память E и κ на Δ_N — в чистом виде невыполним:
  - отправленная поправка E уже сидит в измеренной руке x, и вычесть её ещё раз значит отменять собственную поправку;
  - двойной счёт VS-T идёт от ещё не пройденной части пути плана. Знать её — значит знать путь плана, а это модель руки.
- **Вариант (а)** — G-auto плюс член прицела `A = s* − (g_R − p_R)` — отпадает:
  - полный Base, из которого берётся s*, идёт без помехи (`control`), его префикс общий с опорным планом R;
  - поэтому s* — естественный прицел того же плана, и A — это ошибка модели по построению.
- **Выбрано: VT-m** — машина PBVS (путь плана по модели A и учёт z) с целью VS-T:
  - VT-m − VS-T: у обеих s*, разница только в памяти — **В1**, вопрос рецензента;
  - VT-m − PBVS: обе на одной модели, разница только в цели — **В2**;
  - пол шума модели меряется (`a_R` опорного плана), а не допускается.
- Формула, правило пола шума и толкование с предсказанием против нас — отдельной записью до кода. B идёт после C.

### 2026-10-22 — ветка VT-m: формула и правила (до кода и до данных B)

**Закон.** VT-m — это PBVS-B этого спека с целью VS-T. От PBVS-B (§2) берётся всё: якорь (b), путь плана w по модели руки, учёт z, окно G от t_e до первой «закрыть», мёртвая зона и форма команды `a_xy = clip(clip(a_plan) − λ e / G_POS, ±1)`. Меняется только ошибка, на xy:
- `e(t) = (x(t) − w(t)) − (p(t) − p(t_obs,N)) + a_N`;
- `a_N = (ŵ_N(t_c,N) − p(t_obs,N)) − s*`.

**Из чего состоит a_N:**
- **ŵ_N(t_c,N) — намеченная точка, а не измерение.** Это положение схвата на шаге t_c,N первой строки «закрыть» плана N, предсказанное моделью руки по строкам плана от его прибытия: `ŵ_N(t_c) = x_N + Σ_{j=t_a}^{t_c−1} D_j`. Модель и приращения D_j те же, что у пути w.
- **t_c,N = t_obs,N + k_c**, где k_c — первая строка с командой «закрыть» (последний столбец больше нуля) среди строк, которые план ещё исполнит: `k_c ≥ t_a − t_obs,N`. Строки, съеденные задержкой, не считаются.
- **s* — измеренная величина.** Это смещение «схват − предмет» на xy на шаге первой «закрыть» парного полного Base, эпизода без помехи. Берётся как у VS-T.
- **ŵ_N и s* — разные величины.** Первая предсказана моделью по строкам плана, вторая замерена в другом эпизоде. Величина не сравнивается сама с собой.
- a_N считается один раз, при прибытии плана N, и постоянен, пока N исполняется.

**Параметры:**
- модель руки и порог берутся из `band_eps.json`: модель A (G 0.0025, B 0.79), δ = 5 мм. Это модель PBVS и порог VS-T и V2eps;
- λ = 0.3 наследован, без подбора (ниже).

**κ отдельно не входит.** Как план N обошёлся с увиденным сдвигом Δ_N, видно прямо по его строкам, это уже сидит в ŵ_N. Если поставить поверх ещё κ закона З1, увиденный сдвиг посчитается дважды.

**Когда a_N не применяется.** Тогда a = 0, и под этим планом VT-m работает как PBVS на 5 мм. Таких случаев три:
- **План N наблюдён до t_e**, то есть не видел сдвига. По разбору (а): Base идёт без помехи и делит префикс с планом, поэтому прицел такого плана совпадает с s* с точностью до ошибки модели. Его a — это пол шума: он считается и пишется, но не применяется.
- **В плане N нет строки «закрыть»** среди строк, которые он ещё исполнит.
  - Зажим к концу плана не берётся: он сравнил бы с s* точку до захвата и тянул бы к позе захвата раньше времени. Ровно это и было провалом VS-T.
  - Пропуск шага тоже не берётся: он выключил бы и слежение за свежим сдвигом.
- **s* нет**: парный Base не закрылся.

Счётчик `no_aim` — шаги окна под планом, наблюдённым после t_e, у которого a не определён.

**Счётчики в записи `vtm`:**
- s* и счётчики PBVS: `steps_window`, `steps_acting`, `sum_e`, `max_e`, `flips`;
- `steps_aim` — шаги окна, где a применён;
- `no_aim`;
- `a_floor` — a плана, исполнявшегося на шаге t_e;
- `a_first` — a первого плана, наблюдённого после t_e, у которого a определён.

**Пол шума — числом, до данных.**
- В эпизоде пол — это `|a_R|`, где `a_R = a_floor`. Сигнал — `|a_N − a_R|`, где `a_N = a_first`. Эпизод входит, если определены оба.
- **Правило.** Считается по объединению двух клеток. Если медиана `|a_N − a_R|` не меньше 2 × медиана `|a_R|`, исходы VT-m показательны. Иначе ноль VT-m — исход (iii) ниже — объявляется непоказательным («знание утонуло в невязке модели»), и тезис им не усиливается.
- Положительный исход, (i) или (ii), снимает тезис при любом поле шума.

**Наследованные λ и порог — смещение в нашу пользу, раскрыто:**
- λ = 0.3 и порог 5 мм взяты у PBVS (§4) и у VS-T без подбора;
- у VT-m иная форма ошибки: в ней есть член a_N, которого нет ни у PBVS, ни у VS-T. λ, подобранный под другую форму ошибки, для VT-m может быть неоптимален;
- подбор под VT-m не делался намеренно: владелец и учебник видели сводки, и любой подбор сейчас был бы post-hoc;
- неоптимальный λ ослабляет VT-m, то есть ту ветку, чей выигрыш рушит наш тезис. Значит, смещение направлено против VT-m и в пользу нашего вывода;
- если VT-m всё равно обгонит G-auto, вывод тем крепче. Если не обгонит, честно говорим, что часть этого может быть ценой наследованного λ.

**Клетки.**
- d = 0 PRO (113 случаев) и d = 10 Plus (187 случаев).
- Полный Base и ветка `VTm` идут в одном процессе, без `--base-prefix`: s* — первое закрытие этого Base.
- Случаи, порядок и группы Base — как у VT2 PRO и VT3d10 Plus, то есть как у линий 2 и 3.
- Цена: 0.96 + 2.08 ≈ 3.04 ч ≈ $1.13.
- Стадия — после C.

**Пары** — по правилам чтения VS-T. Base у VT-m тот же, что у VS-T: он детерминирован, и ворота «Base VT1 = V0» прошли. Пары сводятся по `case_id` и `policy_seed`, e у них равны.

**Измерения** (оценка, двусторонний 95%, односторонние границы; кластеры по исходной задаче):
- **Главное — VT-m − G-auto** в каждой клетке. G-auto берётся с пода C: линия 2 PRO при d = 0, линия 3 Plus при d = 10.
- **В1 — VT-m − VS-T** (VT2 PRO, VT3d10 Plus). Ветки отличаются только памятью.
- **В2 — VT-m − PBVS:**
  - при d = 0 PRO — против V2eps: тот же порог 5 мм и та же модель, сравнение чистое;
  - при d = 10 Plus — против V3d10, где порог 26 мм. Здесь смешаны цель и порог, поэтому только отчёт, с этой оговоркой.
- **Отчёт:** счётчики, доля шагов с прицелом, `no_aim`, пол шума.

**Толкование главного (до данных; предсказывает против нас):**
- **(i)** Нижняя односторонняя граница 95% разности VT-m − G-auto больше нуля хотя бы в одной клетке → «плоская кривая» снимается. Вывод: «информация полезна, беспамятная реализация неудачна». Пишем так, даже если это рушит тезис сводки.
- **(ii)** Обе точечные оценки больше нуля, но ни одна граница не исключает нуль → тезис тоже снимается, как неподдержанный: данные склоняются против него.
- **(iii)** Иначе — хотя бы одна оценка не больше нуля и ни одна граница не больше нуля → тезис остаётся только в суженном виде: «цель из показа, использованная с памятью, не обгоняет наш закон в пределах верхних границ X». Добавляются оговорки про пол шума и наследованный λ. Если правило пола шума даёт «непоказательно», тезис этим исходом не усиливается.
- Статью исход не рушит ни в каком случае: VT-m требует захвата из эпизода, которого не было, а у настоящего робота такого знания нет.

**В1 — только отчёт, но с прочтением до данных.** Если нижняя граница VT-m − VS-T при d = 10 больше нуля, провал VS-T под задержкой характеризует конструкцию (беспамятность), а не информацию — как и сказал рецензент. Иначе это не показано.

**В2 при d = 10 остаётся неизмеренным.** При d = 0 он измерен, только если пол шума показателен. Причина: модель руки вносит невязку порядка самой величины (§3: δ_M модели A — 26.2 мм).
