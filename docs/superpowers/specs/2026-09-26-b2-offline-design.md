# B2 офлайн: дешёвый пакет рефлекса — дизайн

Дата: 2026-09-26 · Статус: **записан, до данных** · Тип: **офлайн-отбор** с правилом, записанным до данных. Это не вердикт: решаемость и настоящую задержку меряет GPU-прогон B2+B5 (отдельный спек) · Основа: B1 (`docs/results/b1.md` §6, `docs/results/report.md` §8), диагностика (`docs/results/b1-diag.md`), `docs/roadmap.md` B2

## 1. Зачем

- **Задержку вызова определяет глубина, а не число прогонов** (B1 §6). На GPU, d = 1, задержка в долях RTC: pred 1.06–1.19, точный reflex 1.8–1.9.
- **Значит, `J` — обратный проход через все 5 шагов потока — стоит около 0.7 RTC.** Цель роадмапа — r ≤ 1.2 при потере не больше 1 п.п. решаемости.
- **Диагностика показала, что качество прикидки зависит только от ‖e‖.** Поэтому дешёвые пакеты можно сравнивать офлайн в корзинах ‖e‖ и отобрать 1–3 кандидата в GPU-прогон.

## 2. Чего не делаем

- **Номинал = чанк — не удешевление.** Номинал π(ô_j)[0] при `J` бесплатен: `jax.vjp` в `reflex.first_action_and_jacobian` (`src/reflex.py:22`) и так прогоняет поток вперёд в ô_j и возвращает a0. По `forward_equivalents` `rtc_reflex` дороже reflex. Он остаётся только опорной строкой.
- **low-rank `J` не берём.** Ранг `J` и так не больше 4 (привязанные измерения действия). low-rank экономит байты пакета, а не вычисления.
- **JVP на каждом шаге управления не берём** (роадмап B2): JVP через поток дороже свежего вызова.
- **Замкнутый цикл, решаемость и настоящая задержка** — только в B2+B5 на GPU.

## 3. Кандидаты и цены

Обозначения:
- 5 шагов потока (S = 5), действие размерности A = 6, P = 5 позиций пакета (s = 5);
- **глубина** — последовательные шаги потока после чанка и предсказателя: f — прямой, b — обратный;
- **FE** — forward-эквиваленты на вызов, как в `reflex.forward_equivalents`, VJP считается за 2.

Поток — шаги Эйлера `x ← x + (1/S)·v(o, x, t)` от шума `roll(z, −j)` (`model.action_from_noise`).

| строка | номинал | `J` — производная через | глубина | FE |
|---|---|---|---|---|
| **опорные** | | | | |
| pred | π(ô_j), 5 шагов | — | 5f | 30 |
| reflex (точный) | π(ô_j), 5 шагов | 5 шагов | 5f + 5b | 330 |
| chunk + J (замена `rtc_reflex`, как в диагностике Q2: номинал — чанк политики, а не чанк RTC) | чанк_j | 5 шагов | 5f + 5b | 330 |
| **глубина** | | | | |
| **T_k**, обрезанный `J` | π(ô_j), 5 шагов, точно | последние k шагов; состояние потока до них — константа (`stop_gradient`) | 5f + k·b | 5 + 5(5 + 12k) |
| **W_k**, тёплый старт | состояние чанка на шаге S−k (при o₀), сдвинутое `roll(x, −j)`, затем k шагов при ô_j с t от (S−k)/S | эти k шагов | k·f + k·b | 5 + 65k |
| **M_m**, короткий поток | m шагов с шагом 1/m от шума `roll(z, −j)` при ô_j | эти m шагов | m·f + m·b | 5 + 65m |
| **ширина (вторая цена)** | | | | |
| один `J` на все позиции | π(ô_j), 5 шагов | 5 шагов, один раз, в позиции 5 (середина исполняемых 3…7 при d = 3, s = 5) | 5f + 5b | 5 + 25 + 60 = 90 |
| `J` только по привязанным измерениям действия | точно | 5 шагов | 5f + 5b | 5 + 5(5 + 10·A_used), при A_used = 4 → 230 |

- **k и m** — 1, 2, 3.
- **При k = 5 и m = 5** кандидаты T_k, W_k и M_m совпадают с точным reflex. Это проверка в тестах.
- **`J` по привязанным измерениям точен по построению:** непривязанные измерения не меняют исполняемое действие. Офлайн его не меряем, в таблице только цена.
- **FE-цены:** k = 1…3 для T_k дают 90 / 150 / 210, для W_k и M_m — 70 / 135 / 200.

## 4. Данные

- **Как в диагностике** (`src/diag.py`, спек `2026-09-26-b1-diagnostic-design.md` §3), но один чанк: k = 1…7, режим d = 3–4.
- **Seed'ы** — `4000 + LEVELS.index(level)`, новые.
- **Объём:** 12 уровней × 128 состояний × 4 прогона шума действий σ = 0.1.
- **Предсказатели:** learned (основной) и oracle.
  - **Модели мира learned — маковские** из `results/b1/world_models`, а не подовские из B1. Подовские не сохранились: архив с пода собирался без `*.pkl`. Они не одинаковые: на swimmer с маковской моделью pred решает 57% против 43% (`results/demo/wm_check_swimmer.csv`).
  - **SHA-256 каждого `.pkl` входит в замок конфигурации** сырых файлов.
  - **В B2+B5 на под едут эти же файлы,** без переобучения, чтобы офлайн-отбор и GPU мерили одну модель.
- **Oracle** отделяет ошибку дешёвого пакета от ошибки прогноза. phys не берём.
- **Свежий вызов** a* = π(z_k-сдвинутый, o_k)[0], где o_k — реальное наблюдение с шумом. Действия сравниваются как исполненные (`probe.executed`), как в E1b.

## 5. Мерило

Для кандидата c с номиналом nom_c и `J_c`, где e = o − ô:

- **res_c = Σ‖exec(a*) − exec(nom_c + clip(J_c·e, ±1))‖²** — абсолютный остаток против свежего вызова. В `diag.py` это сумма `lin_clip`; у pred — сумма `pred`, у chunk + J — `chunk_lin_clip`. Колонка `res` в `diag.py` — отношение `lin/pred`, это не она.
- **Главная таблица:** res_c в корзинах ‖e‖, медиана по уровням от пуловых сумм по уровню. Края корзин — децили из диагностики (`results/b1/diag/bins.csv`, строки `all`).
- **Рядом — ρ_clip кандидата** относительно его собственного номинала: 1 − Σres_c / Σ‖exec(a*) − exec(nom_c)‖².
- **Сводная доля по уровню** — из пуловых res по k ≤ 7 и ‖e‖ ≤ 2.3:

  R_c = (res_pred − res_c) / (res_pred − res_reflex)

  Это доля выигрыша точного `J` над pred, которую сохраняет кандидат.
- **Защита знаменателя.** Уровни, где точный reflex улучшает res над pred меньше чем на 10%, то есть (res_pred − res_reflex) / res_pred < 0.1, в медиану R не входят. Их R показывается отдельно.

## 6. Правило отбора (до данных)

Считается на learned при k ≤ 7 и ‖e‖ ≤ 2.3; выше прикидка и так слаба (диагностика, Q3).

- **Кандидат проходит,** если выполнены оба условия:
  - медиана R_c по уровням, вошедшим в медиану, ≥ 0.8;
  - res_c ≤ res_pred хотя бы на 10 уровнях из 12.
- **В GPU-прогон B2+B5 идут:**
  1. самый мелкий по глубине прошедший кандидат (при равной глубине — меньший FE);
  2. лучший по R прошедший T_k, если это другой кандидат;
  3. самый мелкий по глубине кандидат с R ≥ 0.9, если это другой кандидат. Причина: 20% потери пользы `J` на D3 — около 1.5 п.п., больше цели в 1 п.п., а связь офлайн-меры с замкнутым циклом неизвестна;
  4. опорные строки: точный reflex, pred, `rtc_reflex`.
- **Единица глубины: f = b = 1.** По B1 обратный шаг стоит примерно как прямой. Тогда глубина равна: pred 5, reflex 10, T_k 5 + k, W_k 2k, M_m 2m. Пример ничьей: T_1 = 6 = W_3, выигрывает меньший FE (90 < 200).
- **Если не прошёл никто,** записываем: «офлайн глубину не срезать без потери > 20% пользы `J`». На GPU тогда идут точный reflex и лучший по R кандидат, как поисковая строка.
- **Строки ширины** (один `J`, привязанные измерения) в правило не входят. Их R и цена идут в таблицу для B5.

## 7. Ожидания (не правила)

- **T_k сохранит больше R, чем W_k и M_m при той же k:** у T_k номинал точный.
- **M_1 — одношаговый поток**, по сути другая политика. Скорее всего провалится на номинале.
- **W_k между ними.** Состояние чанка на шаге S−k получено при o₀, а не при ô_j. Чем больше j, тем больше разница o₀ и ô_j, и тем хуже W_k на дальних позициях.
- **Известный артефакт W_k.** `roll(x, −j)` уносит в хвост j частично расшумлённых строк прошлых позиций чанка. У точного reflex на этом месте iid-шум. Поток в момент (S−k)/S такого не ждёт, поэтому W_k может выглядеть хуже, чем был бы тёплый старт без этого сдвига.
- **Oracle и learned** дадут похожие R: качество прикидки зависит от ‖e‖, а не от источника отклонения (диагностика, Q3).

- **Нагрузка на состояние:** 2 предсказателя × 7 позиций × 11 пакетов ≈ 154 вычисления `J`. Это столько же, сколько в диагностике (5 × 31), значит около 30–40 минут на Mac CPU.

  1. спек и план пушим до прогона;
